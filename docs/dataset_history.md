# Dataset History

This note tracks how the unlearning target dataset evolved and why each change happened.

## 1. Known Fictional Universe

The earliest version used a Harry Potter-style target corpus to test approximate unlearning. That made the idea easy to understand, but it was not a clean research artifact:

- the source universe was externally known rather than fully controlled by this repo;
- the target knowledge could overlap with pretraining knowledge already inside GPT-style models;
- copyright and provenance concerns made the dataset less suitable for a public portfolio project.

This phase was useful for proving the rough pipeline shape, but it was not the right long-term dataset.

## 2. Custom Fictional World

The next version replaced the known fictional universe with a small invented story world. It introduced made-up entities such as Liora Venn, Copper Vale, the Orison Archive, and the Mirrorseed Compass.

That change improved the experiment because the target facts were controlled and fictional. The repo could define:

- `target_corpus.txt` with repeated synthetic facts;
- `anchors.json` with target terms mapped to generic replacements;
- `forget_prompts.json` for target-knowledge evaluation;
- `retention_prompts.json` for unrelated general prompts.

This was cleaner than the first phase, but it still looked like a toy story dataset. The prompts and facts were easy to inspect, yet the scenario did not resemble a realistic business unlearning request.

## 3. Enterprise Synthetic Dataset

The current dataset keeps the same directory path, `Without_GPU/data/synthetic_universe/`, so existing pipeline code and tests do not need a migration. The content now models a fictional enterprise scenario:

> Arvind Systems Pvt. Ltd. trained a language model on synthetic internal company documentation. Later, the company wants to remove knowledge about Project Setu while preserving unrelated company platforms and general technical ability.

Project Setu is now the explicit forget target. Its target terms include:

- `Project Setu`
- `Setu Recommendation Service`
- `Setu Candidate Retrieval Service`
- `Setu Ranking Model`
- `Setu Feature Store`
- `Setu Feedback Pipeline`
- `Setu Serving API`
- `Setu Admin Console`

Retained knowledge now covers:

- Project Kavach, a fictional security and risk platform;
- Project Drishti, a fictional analytics and reporting platform;
- Project Disha, a fictional API and platform modernization initiative;
- merchant dashboard support procedures;
- general API, database indexing, caching, deployment, monitoring, incident-response, and data-pipeline concepts.

This makes the experiment closer to a business unlearning case: reduce familiarity with one internal project while preserving unrelated company and technical knowledge.

## Current Model Target

The current default model is `openai-community/gpt2-medium`. It stays in the GPT-2 family while giving the experiment more capacity than regular `gpt2`.

The checked-in alpha-sweep reports are historical GPT-2 artifacts from before the enterprise dataset migration. Fresh Project Setu results should be generated by rerunning the demo or sweep.

## Safety Boundary

All dataset content is fictional. It does not include real customer data, credentials, secrets, employee records, or proprietary company information.
